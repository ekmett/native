# F16C conversions

`import native.x86.f16c;` exposes binary32 / IEEE binary16 conversions through
`native::minimal`. `native.x86` and `native` reexport it. The implementation
header stays in the global module fragment; this module does not import
`native.simd` or `native.numerics`. F16C supplies conversions, not half arithmetic.

Every call takes an explicit `isa Arch` containing `x86_feature::f16c`.
Its compiler prerequisite closure includes AVX. Call only after
`classify_isa(observe_x86_capabilities(), Arch).admitted()` succeeds and inside
a function with a matching compiler target. Admission checks CPUID and enabled
XMM/YMM state separately. These operations require neither AVX2 nor AVX512FP16.

| Call | Input | Output |
| --- | --- | --- |
| `cvtss_sh<Arch, Imm8>(x)` | `float` | `std::uint16_t` half bits |
| `cvtsh_ss<Arch>(h)` | `std::uint16_t` half bits | `float` |
| `cvtps_ph<Arch, Imm8>(x)` | `__m128` | Four half words in low 64 bits of `__m128i`; high 64 bits zero |
| `cvtps_ph<Arch, Imm8>(x)` | `__m256` | Eight half words in `__m128i` |
| `cvtph_ps<Arch, 4>(h)` | Low four half words of `__m128i` | `__m128` |
| `cvtph_ps<Arch, 8>(h)` | Eight half words of `__m128i` | `__m256` |

The widening lane count is mandatory because both packed forms take the same
input type. Packed arguments must have exactly the documented vector type.
Scalar forms use the four-lane instruction with unused inputs zeroed.
All six forms are `noexcept`; this concerns C++ exceptions, not hardware traps.

```cpp
#include <native/attributes.h>
import native.x86.f16c;

constexpr native::isa half_conversion{native::x86_feature::f16c};

// Enter only after admitting half_conversion in baseline caller code.
native_target("f16c")
float round_trip(float x) {
  auto bits = native::cvtss_sh<half_conversion, 0>(x);
  return native::cvtsh_ss<half_conversion>(bits);
}
```

`native::fp16::from_bits()` and `to_bits()` connect scalar storage to these raw
bits. Import `native.numerics` when using that storage. With `native.simd`
imported, `simd<float,N,Arch>::to_native()` and `from_native()` connect packed
float registers. The existing storage and bridge contracts remain unchanged.

## Rounding and floating-point state

`Imm8` accepts all values from 0 through 255. When bit 2 is clear, bits 1:0
select nearest-even, toward negative infinity, toward positive infinity, or
toward zero, respectively. Bit 2 selects the current MXCSR rounding direction.
Bits 7:3 are ignored, so **`_MM_FROUND_NO_EXC` does not suppress F16C exceptions**.
Use `0` for nearest-even or `4` for MXCSR rounding.
[Intel SDM, Volume 2C, VCVTPS2PH](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2c-manual.pdf).

Widening is exact for finite inputs, including half subnormals, irrespective of
DAZ. Narrowing ignores FTZ and honors DAZ for binary32 subnormal inputs.
Otherwise tiny results can become subnormal or signed zero. Overflow returns
infinity or the largest finite magnitude according to sign and rounding.
Both directions preserve the signs of zeros, infinities and NaNs. Widening
moves the half fraction into binary32 fraction bits 22:13. Narrowing retains
binary32 fraction bits 22:13. NaN results have the destination quiet bit set;
a signaling NaN raises invalid.
[Intel SDM, Volume 1, §14.4](https://cdrdv2-public.intel.com/843827/253665-sdm-vol-1-dec-24.pdf).

Narrowing can signal invalid, denormal, overflow, underflow and precision;
widening can signal invalid. Status bits accumulate in MXCSR. Exception masks
control trapping; these functions leave masks and other controls alone. With
DM masked and either UM or PM unmasked, a binary32 subnormal input can trap
with DE, UE and PE set. Exact tiny results can trap when underflow is unmasked.
[Intel SDM, Volume 1, §14.4](https://cdrdv2-public.intel.com/843827/253665-sdm-vol-1-dec-24.pdf).

Clang's ordinary conversion intrinsics can be optimized away when their result
is unused. The wrappers therefore use volatile assembly with register operands
and a memory clobber to retain each instruction and order it with MXCSR access.
They carry no `const` or `pure` attribute. This also keeps VEX F16C encodings
explicit. The assembly supports both AT&T and Intel syntax.
[LLVM's F16C intrinsic definitions](https://clang.llvm.org/doxygen/f16cintrin_8h_source.html).

## Validation

The fixture compares every half bit pattern against a separate integer decoder.
Narrowing uses an integer quotient/remainder oracle with directed neighbors of
every finite half value and midpoint, random binary32 inputs, every immediate
byte, every rounding direction and all FTZ/DAZ combinations. It checks masked
status flags, discarded outputs, cleared upper words and restored MXCSR.
On Linux, child processes check unmasked exceptions through saved signal state.

Compile-failure tests cover missing features and targets, invalid immediates,
missing or invalid lane counts, and wrong vector types. Object inspection checks
all six used and discarded forms under explicitly disabled optional features,
both assembly syntaxes, and a baseline hub importer. The top-level fixture uses
`find_package(native)` with installed modules and public headers only.
